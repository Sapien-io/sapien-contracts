ERC-8004 VNext Detailed Plan

Scope and Locked Decisions





Strict on-chain ERC-8004 compatibility (no legacy compatibility paths).



Deterministic AgentAccount execution model for all participant actions.



Support both registry modes:





Internal protocol-managed ERC-8004 registries.



External canonical ERC-8004 registries via adapters.



Wallet rotation must preserve in-flight claims, rewards, stake locks, and reputation.

Current Hotspots To Replace





Shared participant structs are address-based in src/interface/ISharedTypes.sol (for example Project.originator, Claim.contributor, Validation.validator).



Authorization is wallet-bound in src/SapienCore.sol and src/ValidationOracle.sol (for example msg.sender ownership checks).



Reward accounting is address-keyed in src/Rewards.sol.



Reputation and skill state is address-keyed in src/SapienTrust.sol.

VNext Architecture





Introduce canonical identity key:





agentKey = keccak256(abi.encode(chainId, identityRegistry, agentId)).



Introduce deterministic execution account per identity:





AgentAccount deployed via CREATE2 from agentKey.



Route participant actions through AgentForwarder + EIP-712 typed actions.



Validate signatures with ECDSA for EOAs and ERC-1271 for contract signers.



Use AgentIdentityResolver to abstract internal/external registry lookups.



Keep vault token accounting ERC-4626 address-native, but lock/slash by identity via resolver mapping to active AgentAccount.

Add correlation IDs linking protocol validation lifecycle to ERC-8004 validation requests/responses.

Wallet Rotation Design





Rotation updates controller authority for the same agentKey/AgentAccount.



Rotation transaction requirements:





Current controller authorization.



New controller acceptance proof.



Fresh nonce and deadline.



State that must remain unchanged across rotation:





Active claims, assignments, in-flight stake, pending rewards, trust score, skill flags.

New invariants





Identity reward conservation per project/token.



Locked stake never exceeds identity stake across rotation.



No orphan identity state after registry mode switch.



Delegated actions always attributed to the signed agentKey.



No replay across controller rotations (nonce monotonicity).

Delivery Sequence





Step 1: Interface freeze and identity key definitions.



Step 2: Internal registries + external adapters + resolver.



Step 3: AgentAccount + factory + forwarder.



Step 4: Core/oracle/rewards/trust identity-keyed refactor.

Exit Criteria





No participant-critical protocol state is keyed by raw wallet address.



All role actions are executable via AgentAccount with EIP-712/ERC-1271 auth.



Rotation preserves all economic and lifecycle state.



Both registry modes pass identical end-to-end lifecycle tests.
